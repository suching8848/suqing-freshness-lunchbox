与 Loot Tracker 1.8.5 共用库存选择接口时，保留搜刮记录及密封限制。

可选配套「蘇清的返鲜餐盒外挂减重修复」`SuQingLunchboxAttachedWeight_4222` 让背包底部餐盒的内容物按当前升级比例减重。适用于 B42.22.2 单人，需要 ZombieBuddy 2.3.4 和 Java 模组批准。工坊同包提供，使用时与餐盒本体、ZombieBuddy 一起启用，批准 Java 模组后完整重启。停用配套并重启可恢复原生外挂负重。原生减重已离线验证，本机游戏日志确认补丁已加载并应用，游戏内实际重量待测。

放入可返鲜的食物，右键餐盒开启批次。封盒期间可以搬动整个餐盒，内容物锁定。到期时按开始记录的名单一次结算，原有食物恢复至新鲜并解锁。餐盒回到加载范围后会处理已到期的批次，时长按游戏时间计。

## 默认规格与设置

- 容量 **4**、自重 **1.0**、基础减重 **50%**，以当前原版 `Base.Lunchbox` 为参考。
- 餐盒独立沙盒包含总开关、初始容量、批次时长和是否允许变质食品。冰箱使用自己的设置。
- 基础容量默认4，范围1–30，仅用于新餐盒首次初始化。已有餐盒和升级账本继续使用其容量。
- `SuQingFreshnessLunchbox.BatchHours` 默认 **12 游戏小时**，范围 **0.25–24**。开始时固定本批次的结束时间。总开关控制是否可以开启新批次。
- 一批只收直接存放且具备标准腐坏周期的食物。烧焦食物、受精蛋、被污染的食品及无法安全处理的物品需要先取出。变质食品按沙盒许可处理。
- 完成时保留原物品的份量、生熟、毒素与污染数据，并恢复正常腐坏与烹饪属性。批次结束后再停用或回退版本。其他模组直接改原生库存的行为需单独验证。

保留原版餐盒 `MaxItemSize=1`，只收标准Food；实际拖放及与其他模组食品的组合由用户验收，容量提升不等同于取消尺寸限制。持续供电/换电不属于本候选机制。

## 制作与容器升级

使用原生制作菜单，提供两条同产物配方，螺丝刀均保留不消耗：

1. 原版空餐盒×1、怀表×1、电子表×1、经典腕表×1、电线×2。
2. 小金属板×2、怀表×1、电子表×1、经典腕表×1、电线×2。

电子表与经典腕表分别兼容原版常见左右手/颜色版本，三类钟表必须是三件不同实物。取消、失败和付款由原生制作处理，不另设重复返料循环。餐盒改造路线要求输入为空、移出双手且没有容器升级账本；金属板路线不要求先有餐盒。

普通容器升级主模组 `SuQingContainerUpgrade_4221` **1.0.3** 已内置本餐盒支持，无需另外启用餐盒兼容子模组。返鲜餐盒不依赖普通容器升级；未安装或未启用普通升级时，制作、收纳与返鲜仍可独立使用。

启用支持本餐盒的新版普通升级后，沿用其五档容量12/20/30/40/49、减重90/93/95/97/99及材料、技能、付款账本、精确还原和实付50%返料规则。升级和还原前清空、移出双手并从挂点卸下。返鲜模块只在第一次初始化设置基础容量，之后不会把强化成果写回4。此支持不把餐盒自动加入EX或Auto。

本轮轮廓修正只更新返鲜餐盒到0.1.0-rc.5，现已安装的普通容器升级1.0.3保持。此前普通1.0.0的完整备份和独立恢复目录、正式档追加餐盒ID及新档default保持原状的事实见历史部署记录。其他环境手动替换时应正常退出游戏，同一Mod ID不要保留多个可加载副本。不需要普通升级时仍可单独使用返鲜餐盒。

已有 `Codex_SuQingWearableCompat_4221` 仍承担HavenFall EX等其他兼容职责，本次移除餐盒专属子模组不代表应停用它；保持其原有按需启用状态。

沿用rc.3对餐盒制作前置检查加载时机的修正，保留现用HavenFall EX制作链的严格检查，以及既有EX配方和账本拦截规则。用户仍需验收HavenFall包的EX升级／还原、ESHF原生转换对EX账本的拦截，以及两条餐盒配方；这是当前兼容链的候选修正，游戏内效果尚未确认。
