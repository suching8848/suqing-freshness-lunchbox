# 蘇清的返鲜餐盒 / SuQing's Freshness Lunchbox

工坊条目：[已上传并核验的私有条目](https://steamcommunity.com/sharedfiles/filedetails/?id=3834693433)。源码仓库：[suching8848/suqing-freshness-lunchbox](https://github.com/suching8848/suqing-freshness-lunchbox)。2026-11-06已完成私有上传与原生内容读回；未公开，游戏内验收状态不变。

Project Zomboid B42.21 单人候选版 **0.1.0-rc.5**。本项目仅含一个 Mod ID：`SuQingFreshnessLunchbox`；食品容器：`SuQingFreshnessLunchbox.FreshnessLunchbox`。

基于原版餐盒的独立食品容器，支持左右任一只手提握。食品直接放入或取出，保留原物品；按各自原生新鲜期逐渐减龄，全部同期处理。放在人物身上、背包、地面、家具和车内均可在有效加载状态下工作；有可靠原食品、餐盒及启用时段记录时，返回区域后补算经过的游戏时间。退出游戏的现实时间不计入，手动关闭和模组停用的时间不补算。

当前为 **rc.5地面轮廓修正候选**。用户已反馈除模型轮廓贴合外没有其他明显问题；这项反馈不代表全部兼容场景均已验收。本轮采用实际地面FBX、现有材质与原生投影参数，生成独立32×32透明世界物品贴图，通过 `UseWorldItem` 用于原生sprite回退。背包物品icon、模型、返鲜逻辑、配方、容器升级与沙盒规则保持。

本轮备份、校验和个人部署以[轮廓修复记录](docs/personal-outline-20261106.md)为准；此前rc.4三项修复见[历史记录](docs/personal-hotfix-20261106.md)。没有启动或操作游戏，没有提交Git或发布工坊。

## rc.5轮廓修正与限制

- 保留库存独立图标，新增 `media/inventory/world/WItem_SuQingFreshnessLunchbox.png`，启用 `UseWorldItem=true`，保持 `ScaleWorldIcon=1`。
- 世界贴图来自原始网格、FBX节点变换、原UV和现用材质的离线渲染；不是将库存icon或封面缩小。落地点对应32像素画布的(16,24)，3D模型缩放仍为0.4。
- 原生有效模型图集仍优先使用；没有有效图集时才采用专用世界贴图。没有修改Java、全局渲染或PZO配置。
- 专用贴图是固定yaw=0的回退投影，可改善原“正面提手箱”图标与薄餐盒的外形差异；不能宣称任意旋转、扩展摆放和相机偏移均逐像素贴合。最终效果由用户重进后验收。
- 既有餐盒读档时自然读取当前脚本和世界贴图，无需重新制作、迁移物品或回滚存档。

## 默认规格与设置

- 容量 **4**、自重 **1.0**、基础减重 **50%**，以当前原版 `Base.Lunchbox` 为参考。
- 独立沙盒：返鲜总开关、基础容量、恢复时间、允许变质食品。
- 基础容量默认4，范围1–30，仅新餐盒首次初始化采用；已有餐盒及升级账本不随滑块变化重写。
- 恢复时间默认10游戏小时，范围0.25–1000。每个有效游戏小时减少 `食物原生新鲜期 / RestoreHours` 的年龄，最低0。0.25表示每15有效游戏分钟减少一个完整新鲜期，深度腐坏仍可能需要更久。
- 允许变质默认开启。只处理直接存放的标准可腐坏Food；烧焦、受精蛋、无有效保鲜期等不处理。返鲜不补吃剩份量，不清除毒素或污染，不改变生熟。

若世界的原版“移除腐坏食品”参数为非负值，或无法可靠读取，本候选跳过已经变质的食品，并在右键提示中说明；不改动世界参数。允许变质返鲜需要该原版参数为负值。这样避免暂时伪装新鲜来逃过原版删除判定。

补算采用最多128段的启用／设置历史。食品首次放入、换盒、缺失历史、外部Lua改龄或无法证明连续性的情况会重新建立起点，不领取过去的返鲜时间。超过保留历史的区间也不补算。其他模组若直接通过Java同时修改食品年龄和时间戳，无法保证完整识别，属于待验证兼容范围。

保留原版餐盒 `MaxItemSize=1`，只收标准Food；实际拖放及与其他模组食品的组合由用户验收，容量提升不等同于取消尺寸限制。持续供电/换电不属于本候选机制。

## 制作与容器升级

使用原生制作菜单，提供两条同产物配方，螺丝刀均保留不消耗：

1. 原版空餐盒×1、怀表×1、电子表×1、经典腕表×1、电线×2。
2. 小金属板×2、怀表×1、电子表×1、经典腕表×1、电线×2。

电子表与经典腕表分别兼容原版常见左右手/颜色版本，三类钟表必须是三件不同实物。取消、失败和付款由原生制作处理，不另设重复返料循环。餐盒改造路线要求输入为空、移出双手且没有容器升级账本；金属板路线不要求先有餐盒。

普通容器升级主模组 `SuQingContainerUpgrade_4221` **1.0.3** 已内置本餐盒支持，无需另外启用餐盒兼容子模组。返鲜餐盒不依赖普通容器升级；未安装或未启用普通升级时，制作、收纳与返鲜仍可独立使用。

启用支持本餐盒的新版普通升级后，沿用其五档容量12/20/30/40/49、减重90/93/95/97/99及材料、技能、付款账本、精确还原和实付50%返料规则。升级和还原前清空并移出双手。返鲜模块只在第一次初始化设置基础容量，之后不会把强化成果写回4。此支持不把餐盒自动加入EX或Auto。

本轮轮廓修正只更新返鲜餐盒到0.1.0-rc.5，现已安装的普通容器升级1.0.3保持。此前普通1.0.0的完整备份和独立恢复目录、正式档追加餐盒ID及新档default保持原状的事实见历史部署记录。其他环境手动替换时应正常退出游戏，同一Mod ID不要保留多个可加载副本。不需要普通升级时仍可单独使用返鲜餐盒。

已有 `Codex_SuQingWearableCompat_4221` 仍承担HavenFall EX等其他兼容职责，本次移除餐盒专属子模组不代表应停用它；保持其原有按需启用状态。

沿用rc.3对餐盒制作前置检查加载时机的修正，保留现用HavenFall EX制作链的严格检查，以及既有EX配方和账本拦截规则。用户仍需验收HavenFall包的EX升级／还原、ESHF原生转换对EX账本的拦截，以及两条餐盒配方；这是当前兼容链的候选修正，游戏内效果尚未确认。

## 美术、来源与验收

左右手模型、XML、地面模型和纹理基于本机原版Lunchbox独立衍生，使用新路径和独立GUID，保留各自骨骼、权重及提握动作，不覆盖原版。原始网格来源必须如实标为Project Zomboid原版资源衍生，不能称原始网格完全自制。模型及素材证据保留在 `art/model`。

封面以用户原始人物设定及已认可的返鲜冰箱系列图为参考。小尺寸模组icon和透明物品icon独立生成，不缩小封面代替。母版、imagegen提示词和导出资源保留在 `art`。

离线验证覆盖本轮功能、原生解析、Lua编译、双语、模型及兼容边界。真实拖放、左右手换手、走跑/另一手共存、落地拾取、车辆/家具位置、保存重进和Viewpoint第一/第三人称外观由用户完成。代码或资产解析通过不等于游戏内通过。
